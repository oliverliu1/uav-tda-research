## The central finding that drives this roadmap

The paper's entire Results section (binary AUC `0.86 ± 0.00`, the per-attack attribution table, the binary-AUC bar chart) was produced by **`tools/quick_unsup_probe.py` and `tools/diagnose_c2_scaling.py`, which were never committed and no longer exist**. What survives is only their *output*:

- `results/tables/probe_distances{,_seed7,_seed123}.csv` — per-flow probe distances (seeds 42, 7, 123)
- `paper/{PROBE_RESULTS,MULTI_SEED_VARIANCE,C2_NORMALIZATION_DIAGNOSTIC}.md` — derived AUC tables

`pipeline.py`'s `unsupervised` phase computes a **materially different** quantity (all test flows, no top-K/δ approximation, seeds 42/7/**2024**, **max-pooled** combined score rather than the probe's **summed** score, writes `unsupervised_*.csv` not `probe_distances*.csv`). It cannot regenerate the paper.

**Therefore the first and non-negotiable phase is to recover the lost probe/metrics code as tested modules, using the surviving CSVs as golden-master oracles.** Everything else builds on that foundation.

---

## Guiding principles

1. **Characterization-first refactoring.** The monolith has no tests. Before moving any logic, pin its current output with golden-master tests (existing CSVs are the oracle). Refactor only behind a green test. (Feathers, *Working Effectively with Legacy Code*.)
2. **`pipeline.py` stays runnable until the package reproduces it.** We do not delete the monolith; we strangle it (Fowler's strangler-fig) — new package modules take over one phase at a time, each proven equivalent to the monolith's output before the monolith's copy is retired.
3. **Provenance is a first-class artifact.** Every results CSV must be regenerable by one committed command with a recorded seed, config hash, and library versions. No more orphaned outputs.
4. **DRY / YAGNI / TDD / frequent commits**, per the writing-plans skill.

## Phase sequence

Each phase produces working, independently-testable software and ends at a natural review/commit checkpoint.

### Phase 1 — Package foundation + probe reproducibility  ← **detailed plan written**
`docs/superpowers/plans/2026-09-19-plan1-package-foundation-and-repro.md`

Stand up the `uav_tda` package (`pyproject.toml`, pinned deps, `pytest`), port the frozen config with a characterization test, recover the lost **CSV→AUC metrics code** and lock it against `MULTI_SEED_VARIANCE.md`, then reconstruct the **probe runner** as a tested module that regenerates `probe_distances*.csv` and reproduces the paper's AUC table within tolerance. **Deliverable:** the paper's numbers are regenerable by `uav-tda probe --seed 42` from committed code.

### Phase 2 — Strangle the monolith: data + TDA + scoring modules
Extract `config → data → tda → scoring` into package modules, each gated by a golden-master test against the corresponding `outputs/` / `results/tables/` artifact the monolith already produced (`c2_*.csv`, `max_edge_lengths.json`, `persistence_diagrams/*.pkl`, `supervised_summary.csv`). Wire a Typer/argparse `uav-tda` CLI mirroring the monolith's subcommands. Retire each `pipeline.py` phase only once its package twin is proven equivalent. **Deliverable:** `pipeline.py all` reproducible via `uav-tda all`; monolith reduced to a thin shim or deleted.

### Phase 3 — Correctness & scoring fixes the paper already promised
Implement the Section-V corrections as tested code: **per-manifold Z-score normalization** on held-out validation Normal (replacing the unweighted sum), the extended per-call **W₂ timeout** that removes the seed-123 C2 artifact, and reconcile the **sum vs. max-pool** combined-score discrepancy so one definition is used everywhere. Regenerate `C2_NORMALIZATION_DIAGNOSTIC.md` from committed code. **Deliverable:** paper's "deferred to full manuscript" scoring corrections are done and reproducible; revisable-abstract numbers can be refreshed if desired.

### Phase 4 — Statistical rigor: 10 seeds + bootstrap CIs
Generalize the seed loop to N seeds, add bootstrap confidence intervals for every AUC, and emit a single `results/tables/manifold_attribution.csv` + `binary_auc.csv` with mean/std/CI that the paper's table and TikZ chart read from. Add a script that emits the LaTeX table/pgfplots coordinates directly, so paper and code never drift. **Deliverable:** 10-seed results with CIs; paper figures generated from data.

### Phase 5 — Time-windowed variant (the manuscript's lead contribution)
Design and build the time-windowed persistence variant: aggregate flows into temporal windows, compute one diagram per window per manifold, score per window. Compare per-flow vs. windowed at matched compute budgets (AUC vs. latency vs. attribution resolution). This is net-new methodology — it gets its own brainstorming pass before its plan. **Deliverable:** windowed detector + the per-flow-vs-windowed comparison table/figure.

### Phase 6 — Deployment characterization + exact Wasserstein
Two hard, somewhat independent problems:
- **ARM latency harness**: a reproducible benchmarking script profiling per-flow and per-window inference on ARM-class hardware, emitting a latency table.
- **Exact Wasserstein on full test**: solve the ~74h / Hera-hang problem (batching, caching baselines, exact-vs-Hera fallback with per-call timeout, possibly `scipy`/POT exact matching for pathological diagrams, checkpointed resumable runs). **Deliverable:** definitive full-test AUCs replacing the probe approximation, plus the latency characterization.

### Phase 7 — Hygiene, CI, docs (folded in continuously, finalized here)
`ruff` + `black` + `mypy` config, GitHub Actions CI running the fast test suite on every push, a `Makefile` / task runner, a `data/README` documenting the immutable dataset, quarantine of `poster_eda/` (known data-leakage backup) and `scripts_archive/` behind an `archive/` dir with a DEPRECATED note (not deleted — preserve history), and a top-level README that documents the one-command repro path. Update `CLAUDE.md` to describe the package, not the monolith.

## Cross-cutting risks to track

- **Probe reconstruction may not be bit-exact.** We only have the probe's *outputs* and a prose description, not its source. Acceptance is therefore AUC-level (±0.01 vs. `MULTI_SEED_VARIANCE.md`), with per-flow distance correlation as a secondary check. If reconstruction can't hit tolerance, the fallback is to treat the surviving CSVs as the frozen provenance and document the reconstruction as "equivalent method," not "the original."
- **Hera nondeterminism.** Approximate mode + tiebreaking make exact reproduction seed-sensitive; tests must use tolerances, never equality, on any freshly-computed distance.
- **`data/UAVIDS-2025.csv` is gitignored and large.** Repro depends on it being present; document its provenance and checksum so a fresh clone can be made whole.
- **Don't delete what you didn't create.** `poster_eda/`, `scripts_archive/`, and `outputs/` get archived/documented, not `rm`'d, unless you explicitly confirm.
